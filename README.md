# 抖音公开分享媒体 CLI

这是可单独放入 GitHub 仓库的 **Python 命令行工具**，不是整套工作台，也不含网页服务、登录功能、下载样本、个人配置或第三方项目源码。

## 使用范围与授权

仅下载你有权保存和使用的公开媒体。请遵守平台规则及版权规则；本工具不提供或绕过登录、付费、私密内容等访问限制，不保证取得任何内容的使用授权。不要将下载成功理解为可转载或可商用。

## 环境

- Python 3.10 或更新版本，程序与测试仅依赖 Python 标准库。
- FFmpeg，须支持 MP4/MOV、目标视频解码器、AAC 及 null 输出。
- 优先使用环境变量 `MEDIA_FFMPEG`，其次使用 `PATH` 中的 `ffmpeg`。
- 如果系统已安装可选包 `imageio_ffmpeg`，还会尝试该包提供的 FFmpeg；不要求安装它，不包含任何机器专属查找路径。
- 输出文件系统须支持同一文件系统内的硬链接；不支持时会报错，不会降级为可能覆盖已有文件的写法。

## 下载

在本项目目录执行，将参数中的占位文本替换为自己有权使用的真实分享文本：

```sh
python3 download.py '<分享文本>' --output-dir ./output
python3 download.py '<分享文本>' --output-dir ./output --audio
```

可按需指定 FFmpeg 可执行文件：

```sh
MEDIA_FFMPEG=/path/to/ffmpeg python3 download.py '<分享文本>' --output-dir ./output
```

分享文本须包含允许的 HTTPS 抖音分享链接，建议整体使用单引号包裹。含单引号的文本请按当前 shell 的规则转义。

默认保存源站 `play_addr` 返回的允许 CDN 播放文件，不使用 `download_addr`。不修改视频编码、画面或音轨。源站播放文件可能具有平台标识；本工具不承诺去除标识或获得特定清晰度。

`--audio` 额外将第一条 AAC 音轨无损封装为 `.m4a`，不重新编码、不替换视频音轨。不支持的音轨、无音轨或提取/校验失败会使本次任务失败，不会虚报提取成功。默认允许无音轨视频，JSON 中 `hasAudio` 为 `false`。

## 输出与退出码

正常执行或发生可预期错误时，stdout 只输出一个最终 JSON 对象，无进度日志。`--help` 是例外，输出普通命令行帮助。

成功示例（路径仅为示意）：

```json
{
  "ok": true,
  "videoId": "1234567890123456789",
  "title": "示例标题",
  "sourceUrl": "源视频公开页面地址",
  "videoPath": "/output/1234567890123456789.mp4",
  "audioPath": null,
  "duration": 12.34,
  "hasAudio": true,
  "audioExtracted": false,
  "bytes": 1234567
}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `ok` | boolean | 成功时为 true |
| `videoId` | string | 视频编号 |
| `title` | string | 源站描述，最长 500 字符 |
| `sourceUrl` | string | 公开视频页面地址 |
| `videoPath` | string | 已完整校验并发布的 MP4 绝对路径 |
| `audioPath` | string 或 null | 提取成功的 M4A 绝对路径，未提取则 null |
| `duration` | number | 输入容器报告的时长，单位秒 |
| `hasAudio` | boolean | 原视频是否检测到音轨 |
| `audioExtracted` | boolean | 是否成功另存 M4A |
| `bytes` | integer | 视频文件字节数 |

失败 JSON 为 `{"ok": false, "error": "错误说明"}`。退出码：成功 `0`、失败 `1`、用户取消 `130`。不应把失败时输出目录中原有文件当作本次成功结果。

## 安全与完整性

- 仅允许 HTTPS、443 端口及严格的分享域名、详情接口和 CDN 后缀白名单；每次重定向重新验证。
- 所有 DNS 地址须为公网地址；连接绑定已验证的 IP，同时使用原域名进行 TLS 证书校验，避免再次 DNS 查询带来的重绑定。
- 不读取浏览器 Cookie、不使用登录凭据、不继承 HTTP 代理配置。
- 视频最大 200 MiB，源站声明时长和媒体容器时长都不得超过 1800 秒。
- 有 `Content-Length` 时要求完整匹配；无该头时仍有流式大小限制及完整解码校验。
- 最多使用 3 个去重后的允许播放地址，每条线路最多尝试一次，独立 90 秒下载期限；前一线路超时不会耗尽后一线路的期限。元数据处理期限 30 秒，单次完整媒体处理期限 180 秒。FFmpeg 诊断输出最多 256 KiB，超限会终止处理。
- 媒体先写入输出目录内部随机私有临时目录的 `.part` 文件；FFmpeg 以 MP4/MOV 输入方式完整解码视频和全部音轨，失败不发布。没有仅验证文件头或只检查音频。
- 音轨提取不使用 `-t` 或 `-fs` 截断；提取后再次完整解码并比较容器时长，允许最多 0.5 秒容器封装差异。单个音轨文件限制 200 MiB。
- 校验后通过硬链接原子发布单个完整文件；已有名称（包括符号链接）不覆盖，并发任务自动选择编号后缀。MP4 与可选 M4A 不是跨文件事务，观察者可能先看到完整 MP4；第二个发布失败会撤销本任务刚创建的 MP4 链接。
- 失败或退出清理本任务的临时文件，不清理既有媒体。突然断电或强制杀死进程可能留下隐藏临时目录，应人工核查后清理。

仓库内 `skills/douyin-media-download/` 为可独立安装的完整技能，含 `SKILL.md`、下载脚本与故障处理说明，不依赖原工作台或仓库顶层脚本。

触发示例：“下载这条抖音视频：分享链接”“把这条视频的完整音轨保存下来”。默认保留原视频音轨，明确要求时另存 M4A，不做人声分离。


## 已知限制

源站详情接口不是稳定的公开开放 API，可能变更、拒绝请求或失效。平台限制、地区限制、源站反爬、缺少允许 CDN 地址都会导致失败；工具不尝试绕过这些限制。白名单不应为修复失败而无审查地放宽。

时长来自容器描述并配合完整解码，不是逐帧时间戳的司法级取证。FFmpeg 的解码成功也不能证明源视频在上传前没有缺失。网络无 Content-Length 时无法判断源站原本计划发送的精确长度，但仍必须通过容器完整解码。

仅提供 CLI 核心，不提供在线播放、浏览器 UI、批量采集或商业授权保证。`skills/douyin-media-download/` 为自包含技能包装，不是核心运行依赖。
